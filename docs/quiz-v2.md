# Квиз v2: спецификация и реализация

**Статус: основная воронка для всех посетителей.** Прежняя воронка открывается только по `?quiz=1` (в текущей вкладке). A/B-теста больше нет: раздел 6 описывает, как теперь читать данные.

Ветка `quiz-v2`. Не задеплоено: пуш в `main` публикует сайт (`.github/workflows/pages.yml`), воркер `cf-worker/visits.js` обновляется руками в Cloudflare.

## 1. Аудит по коду

**Подтверждено в коде и исправлено**

| Проблема | Где | Что сделано |
|---|---|---|
| 31.02.1990 принимается: `Date.UTC` нормализует в 03.03, экран показывает «Рыбы 12,6°» | `flow.js`, селекты дня 1–31 без проверки | В обоих вариантах дни, которых нет в месяце, и будущие даты выключены; выбранный несуществующий день сбрасывается (A) или переносится с видимым сообщением (v2) |
| Будущие даты текущего года доступны | `flow.js`, `range(1940, thisYear)` | Выключены |
| Темы: обязательно 2–3 | `dock('s2')`, `S.themes.length < 2` | v2: одна основная цель + необязательные дополнительные |
| Вопрос о партнёре всем | маршрут `s3 → s4` | v2: только «Отношения» → «Посмотреть конкретную связь» |
| «Вот первый абзац» без абзаца | `recovery.sub`, абзаца в разметке s7 нет с тех пор, как убрали опрос | v2: обещания нет; есть ссылка на бесплатный обзор (`reading.html` существует и бесплатен намеренно, см. funnel/README) |
| Ручной ввод места требует UTC-смещение | `cityManualOffset` | v2: выбрать ближайший крупный город в том же поясе; берётся его IANA-пояс на дату рождения, асцендент и дома не показываются |
| Тестовые проходы попадают в шаги | `track()` не смотрит на `src` | В обоих вариантах шаги не отправляются при `src/utm_source = test…/deploy…/…check…` и на localhost |
| Оплаты не делятся по варианту | Ping считает только `paid_m/paid_y` | Ссылка чекаута несёт `astro_v`, воркер пишет `a_paid_*` / `q2_paid_*` |

**Подтверждено, оставлено как есть (вне задачи)**

- Темы уже доезжают до продукта (`product/js/app.js`, импорт `themes` → `S.focus`): первая тема задаёт блок в «Сегодня» и фильтр проводника транзитов. В v2 первой стоит основная цель — ответ реально меняет продукт.
- Языки: 10 локалей, первый заход — по `navigator.languages`, выбор хранится в `astromap.lang`, переключатель виден. По IP язык не выбирается.
- Часовые пояса: город хранит IANA-зону, смещение на дату рождения считает `Intl` браузера, то есть с историческим летним временем той базы, которая есть в браузере.
- Польские тексты прежней воронки в женском роде (README) — новые экраны v2 написаны без рода.

**Гипотезы (не доказаны данными)**

- Отвал на экране даты связан с тем, что первый экран сразу просит дату без объяснения пользы.
- Простые выборы и две промежуточные награды увеличат долю дошедших до пейвола.
- Экран «Карта остаётся, небо меняется» объясняет повторную ценность подписки.
- Ни одна из них не проверяется на 53 стартах; см. раздел 6.

**Не проверено (нет доступа или вне браузера)**

- Реальные устройства, Safari iOS, встроенный браузер TikTok, экранная клавиатура Android. Проверено в Chromium на 320/390 px и десктопе.
- Чекаут Gumroad дальше открытия страницы, покупка, Ping и выдача ключа. Проверено только, что Gumroad сохраняет `astro_v=q2` в параметрах своей страницы чекаута; что тот же параметр приходит в Ping как `url_params[astro_v]`, следует из того, как уже работает `astro_sid`, но живым Ping не проверено.
- Открытие стартового раздела в продукте: логика в `route()` прочитана и проверена по коду, но вход через гейт с настоящим ключом не выполнялся.
- Переводы v2 на 9 языков написаны мной, носитель языка их не вычитывал. Биллинговые строки взяты из уже существующих локалей без изменений.

## 3. Ветвление и данные

```
goal → ctx → dob → sun → tk ─┬─ yes → time ─┐
                             └─ no ─────────┴→ place → core → extra → start ─┬─ (love + connection) → pask ─┬─ yes → pdate ─┐
                                                                             │                             └─ no ──────────┤
                                                                             └─ иначе ─────────────────────────────────────┴→ preview → bridge → pay ⇄ year
```

Шаг, который может выпасть из маршрута, считается стоящим на нём, пока ответа нет: прогресс при ветвлении растёт, а не откатывается. Назад — стрелка в шапке, ответы сохраняются; смена даты, времени или места сбрасывает всё посчитанное из них.

**Состояние** (`localStorage.astromap.funnel`, та же форма, что у прежней воронки, плюс поля v2):

| Поле | Тип | Потребитель |
|---|---|---|
| `v` | `'q2'` | handoff из TikTok (метка варианта на чекауте) |
| `dob` | `{d,m,y}` | расчёт, продукт, reading.html |
| `themes` | `[goal, ...extra]` | продукт: `S.focus`, первая — главная |
| `time` | `{h,min,known}`; `known=false` и `h=null`, если время неизвестно | расчёт, продукт |
| `city` | `{n,cc,lat,lon,tz}`; при «нет в списке» `{n, cc, lat:null, lon:null, tz, approx}` | расчёт, продукт, reading.html |
| `partner` | `{d,m,y}` только при ветке пары, иначе пусто | продукт, превью |
| `goal`, `ctx`, `extra`, `extraDone`, `start`, `tk`, `pWant` | ответы | восстановление квиза; `start` → продукт `startView` |
| `lang`, `savedAt` | | как раньше |

Шаг текущей вкладки — `sessionStorage.astromap.q2.step`: перезагрузка и смена языка возвращают на тот же шаг. Новая вкладка начинает с первого шага, прежние ответы отмечены.

**Примеры**

- *Время известно, отношения, пара.* love → connection → дата → Солнце → «знаю» → 14:30 → Варшава → Солнце/Луна/асцендент (Солнце первым) → +«Себя и границы» → «С неба сегодня» → «добавить» → дата → превью с блоком пары → мост → пейвол. 15 экранов.
- *Время неизвестно, работа.* money → period → дата → Солнце → «не знаю» → Мадрид → асцендента нет («Нужно время рождения»); если Луна сменила знак в тот день — «Овен / Телец» с объяснением, точки Луны на круге нет → … → превью с пометкой «точки на 12:00». 12 экранов.
- *Отношения, но без конкретной связи.* love → needs: шагов пары нет.
- *Пара пропущена.* pask = no → `partner` пуст, в продукт не уходит.
- *Город не найден.* «Моего места нет в списке» → своё название (необязательно) + ближайший крупный город → место хранится с поясом этого города и без координат; асцендент: «Нужно точное место».
- *Ошибка сети на превью.* «Превью не загрузилось. Ответы сохранены.» → повтор или «Продолжить без превью» (мост и пейвол работают без вкладок).

## 5. Проверено

В Chromium (локальный сервер, `src=test`, шаги не отправлялись):

- 31.02 и 29.02.1990 недоступны, 29.02.1992 принимается, будущие день и месяц выключены — в A и v2. В v2 смена месяца с 31 на февраль переносит день на 28 с сообщением «День изменён на 28…».

- Без времени и с Луной, сменившей знак в тот день: показаны оба знака, асцендента нет.
- Назад, перезагрузка (возврат на тот же шаг), смена языка RU → ES на шаге «мост» (тот же шаг, те же ответы).

- Чекаут Gumroad открывается с `astro_v=q2`, месячный план, 799 (покупка не выполнялась).
- 320 px: на всех шагах нет горизонтальной прокрутки; цели касания ≥ 44 px, кроме ссылок внутри юридического текста (прежний стиль).

- Вариант A после изменений: дата → темы работает как раньше.

Клавиатура: барабаны — `role=spinbutton`, стрелки/PageUp/PageDown/Home/End; карточки — radio/checkbox с `aria-checked`, стрелки ходят по карточкам; поиск — combobox со стрелками и Enter; при смене шага фокус на заголовок. `prefers-reduced-motion` отключает плавную прокрутку барабанов и анимацию прогресса. Скринридером вживую не проверялось.

## 6. Эксперимент и измерение

**Что сравниваем.** Период до переключения (прежняя воронка) и после (v2) при тех же ценах, тарифах и порядке тарифов. Это совокупный эффект нового онбординга и пейвола, без контроля внешних факторов.

**Назначение.** Теста нет: квиз v2 видят все. Сравнение с прежней воронкой возможно только «до/после» по `/stats` (старые шаги `s1…s7` против `q2_*`), а это слабее A/B: меняются трафик, креативы и сезон. Если нужен честный тест, вернуть в `<head>` index.html случайное назначение с долей.

**Главная метрика.** Подтверждённые первые оплаты (с октября 2026 — вебхук Stripe, раньше Ping Gumroad; без продлений и тестовых) на старт варианта: `(a_paid_m + a_paid_y) / s1` против `(q2_paid_m + q2_paid_y) / q2_goal`. Вспомогательные: старт → пейвол, нажатия «оплатить», переходы по шагам v2, `q2_err_date`, `q2_place_nf`, `q2_pv_fail`.

**Чего нет в данных.** Шаги — это вкладки, а не люди; свойств (устройство, язык, время на шаге) воркер не хранит — только имя шага, день и страну. Анализ по устройству/языку и времени прохождения потребует хранения событий со свойствами; без персональных данных это возможно, но это отдельное изменение воркера и его не стоит делать без решения.

**Порядок.**

1. До запуска: пройти v2 на реальных iPhone (Safari и TikTok) и Android (Chrome и TikTok), особенно барабаны и поле места под клавиатурой; вычитать переводы носителями; задеплоить воркер (иначе шаги v2 вернут 400 и не посчитаются).
2. После выкладки сравнивать конверсию старт → оплата v2 с последним периодом прежней воронки, помня об ограничениях «до/после».
3. Размер выборки посчитать по реальной базовой конверсии A после того, как появятся первые подтверждённые оплаты: сейчас их ноль, и любая заранее названная длительность была бы выдумкой. Ориентир: при базовой конверсии около 1% для уверенного различия даже в два раза нужны тысячи стартов в каждом варианте — при нынешних ~50 стартах в день тест будет долгим, и это стоит знать до начала.
4. Разбивки по стране и языку — только диагностика.
5. Следующие тесты, если трафика хватит: длина при тех же контролах, затем показ тарифов (месяц и год на одном экране — подготовлено текстами `pay`/`year`, но не сделано).

**Путь после «оплатить» — проверить отдельно, без покупки:** ссылка открывается из TikTok (окно) и Safari, условия и НДС на чекауте, Ping пишет `q2_paid_*`, ключ приходит, продукт открывает выбранный раздел. 0 оплат на 5 нажатий не доказывает поломки.
